### reconstructed A01a - Exact replay of M1 after a completed session
- **Plain English:** The attacker recorded M1 of a successful login and sends the identical bytes again.
- **Attacker:** Passive capture + retransmission on the open channel.
- **Action:** Resend M1 unchanged to the 6LC (clock unchanged, inside DeltaT).
  - 1st delivery: ACCEPT
  - 2nd delivery: REJECT (alias lookup in the 6LC database)
  - 6LC replay-cache sets contain 0 entries (present in the class, never filled by step_ake2)
- **Outcome:** REJECT (alias lookup in the 6LC database)
- **Expected / observed:** REJECT / Step AKE2: AID6LN not found in 6LC database
- **Interpretation:** Rejection comes from the STATE TRANSITION after the first session (the stored Sc and alias are replaced), not from a replay cache or the timestamp (still fresh). This is a property of the reconstructed state update, not a literal paper mechanism.
- **Classification:** Protected in the tested configuration
- **Test:** `test_attack_lab[A01a-reconstructed]`

### reconstructed A03a - Timestamp refresh on an intercepted, undelivered M1 (delay attack)
- **Plain English:** The attacker blocks M1, waits until it is stale, rewrites only the timestamp to 'now' and delivers it.
- **Attacker:** Active man-in-the-middle on the channel; no secrets needed.
- **Action:** Replace T6LN by the current time (all other fields untouched), deliver to the 6LC, withhold M2.
  - forged M1: ACCEPT
  - attacker withholds M2 (sensor never sees it)
  - sensor's next honest M1: REJECT (alias lookup in the 6LC database)
- **Outcome:** ACCEPT (-)
- **Expected / observed:** REJECT / accepted
- **Interpretation:** T6LN is not covered by the tag, so the old M1 passes. The controller then updates its state while the sensor does not: the two sides are desynchronised and later honest sessions fail (DoS). The attacker cannot learn SK.
- **Classification:** Vulnerable in the tested configuration
- **Test:** `test_attack_lab[A03a-reconstructed]`
